# 训练、优化与推理文档

## 1. 环境

- 操作系统：Ubuntu 22.04（推荐）；
- Python：3.10；
- 基线：CPU可运行，建议16 GB内存；
- 高级模型：根据模型README选择CUDA/PyTorch，不与基线共用环境。

安装命令：

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
pytest -q
```

## 2. 输入与输出

预处理输入为赛事目录，程序只读取 `初赛-序列数据/**/*.csv`。统一输出字段：

| 字段 | 含义 |
|---|---|
| source_file | 原始来源文件，可追溯 |
| antigen_id/antigen_seq | 抗原名称和可用序列 |
| heavy/light | 抗体重链和轻链 |
| cdrh3 | 原文件提供时保留 |
| raw_label | 原始标签 |
| direction | +1代表原值越大越好，-1代表越小越好 |
| score | 来源内0～1百分位，越大越好 |

## 3. 训练过程

1. 先用每来源5,000条完成冒烟测试；
2. 检查 `benchmark.summary.json` 的跳过文件和样本量；
3. 训练k-mer基线并检查测试来源是否完全隔离；
4. 记录 `metrics.json`；
5. 云端逐步增加每来源上限，而不是一次使用全部数据；
6. 高级模型先冻结预训练编码器，再逐步解冻；
7. 以宏平均Spearman选择模型，Top-10%富集作为业务辅助指标。

## 4. 超参数调优

基线优先搜索：k-mer范围、哈希维数、正则强度、Huber阈值。每次调参使用相同的来源级验证集，最终测试集只能评估一次。

高级模型搜索：学习率、冻结层数、ranking/regression损失权重、负样本比例、最大序列长度、梯度累积和混合精度。

## 5. 测试与错误分析

- 同时报告总体与每来源结果；
- 对只有一个标签值或样本过少的来源，相关系数记为不可计算，不填0；
- 分析有无抗原序列、单双链、真实/预测标签的性能差异；
- 对Top候选检查训练近邻、序列风险和结构置信度；
- 至少运行3个随机种子并报告均值、标准差和置信区间。

## 6. 计算性能

字符k-mer的主要瓶颈是稀疏特征构建和CSV读取。大型语言模型的瓶颈是注意力与显存；结构模型的瓶颈是复合物推理和候选数量。采用分层漏斗，只有前1%～5%的候选进入昂贵结构计算。

## 7. 推理

基线推理读取 `model.joblib`。候选生成示例只做CDR-H3局部突变，正式版应将生成器替换为抗体语言模型或结构条件生成模型，但保持统一CSV输出，便于后续评价和复现。
