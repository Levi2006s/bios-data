## 5. 标签统计

| 标签字段 | 文件数 | 初步含义 |
|---|---:|---|
| `fitness` | 78 | 各数据集自己定义的适应度或归一化标签，含义并不完全一致 |
| `Pred_affinity` | 2 | 模型预测的亲和力，属于弱标签 |
| `Kd [M]` | 1 | 解离常数，通常越小越好 |
| `KD [bind/no bind]` | 1 | 二分类结合标签 |
| 没有可直接识别的数值标签 | 1 | 需要单独解析或作为无标签数据 |

程序对方向的初步判断是：50 个文件“数值越大越好”，32 个文件“数值越小越好”，1 个文件没有方向。

这个方向只是基于字段名和已有规则的自动推测，不能直接当作最终真值。特别是名为 `fitness` 的字段，背后可能来自 KD、IC50、富集度、二分类结果或作者自定义变换。下一步应查原论文或数据说明，为每个来源建立人工确认的标签字典。

没有把所有标签合成一个全局平均值，因为不同文件的单位和物理含义不同，直接求平均没有意义。每个文件的标签最小值、平均值和最大值已经写入 `audit.csv`。

### 需要重点检查的异常

1. 来源 22 的 `proteinbase_all_data_28_01_2026.csv` 有 5,253 行，字段为 `id, name, sequence, author, designMethod, evaluations`。它没有当前流程支持的直接数值标签，而且重链候选长度为 7–822。它更像通用蛋白或无标签设计集合，应放入 `Auxiliary/Quarantine`，不能直接当抗体监督数据。
2. `AbRank_dataset.csv` 有 192,559 条抗原字段包含非标准字符，只有 149,797 条通过当前检查。需要查看这些值是名称、占位符、多条序列拼接，还是确实损坏。
3. `AbRank_dataset.csv` 的重链最长达到 462，需要检查是否存在多链拼接、全长构建体或格式问题。
4. 来源 13 的两个 Phillips 数据文件分别有 953 和 921 条轻链未通过检查，而且没有一条合法轻链。它们可能是无轻链抗体、占位符，或轻链格式与当前规则不同。
5. 来源 3 的两个大文件只有 747,501/3,163,621 行有数值预测标签。未标注行不能进入普通监督训练，但可以保留作无标签或生成候选数据。

## 8. 如何复现

在项目根目录执行：

```powershell
python -m bioos_benchmark.cli audit `
  --data-root "C:\Users\25843\Downloads\第四届Bio-OS开源大赛数据" `
  --output "data\processed\audit.csv"
```

生成两个结果文件：

- `data/processed/audit.csv`：每个文件一行，适合在 Excel 中查看；
- `data/processed/audit.summary.json`：全局汇总，适合程序读取和写报告。

Python 调用接口：

```python
from pathlib import Path
from bioos_benchmark.audit import audit

summary = audit(
    data_root=Path(r"C:\Users\25843\Downloads\第四届Bio-OS开源大赛数据"),
    output=Path("data/processed/audit.csv"),
    compute_hash=True,
)
```

接口返回一个字典，包含文件数、状态、总行数、标签质量、序列覆盖率和输出文件位置。
