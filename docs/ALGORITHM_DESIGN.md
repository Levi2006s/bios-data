# 算法设计文档（第一版）

## 1. 设计思想

本方案把问题拆为“生成—排序—结构验证—多目标筛选”四层。原因是现有公开数据主要是局部突变和活性测量，直接训练端到端从抗原生成中和抗体的数据不足。分层方案便于利用大量无标签序列、少量亲和力数据和结构数据，同时清楚定位误差来源。

## 2. 数据流

```text
多来源CSV/ANDD/INDI2/SAbDab
          │
          ├─字段、单位、方向、来源审计
          │
          ├─来源内百分位标签 y∈[0,1]
          │
          └─来源/抗原簇严格拆分
                    │
     抗体序列 ─────┼───── 抗原序列/表位/结构
                    ↓
            抗原条件排序模型
                    │
生成模型 ──候选──→ 分层结构与可开发性筛选
                    │
                    ↓
              Pareto候选集合
```

## 3. 已实现基线

### 3.1 标签标准化

对于来源数据集 `d` 中的原始测量 `z`，先根据字段判断方向 `s_d∈{-1,+1}`，再计算来源内百分位：

\[
y_i=\frac{\operatorname{rank}(s_d z_i)-1}{n_d-1}.
\]

这样只学习同一实验内的相对优劣，不错误地把不同仪器、单位和实验体系的数值当作可直接比较的绝对值。

### 3.2 特征

- 重链、轻链和抗原序列的2～4字符k-mer哈希；
- 长度、疏水氨基酸比例、净电荷密度、半胱氨酸和脯氨酸比例；
- 缺失抗原或轻链时保留空表示，不虚构信息。

### 3.3 模型

使用Huber损失的弹性网络随机梯度回归：

\[
\min_w \sum_i L_{Huber}(y_i,w^Tx_i)
+\lambda[(1-\alpha)\lVert w\rVert_2^2+\alpha\lVert w\rVert_1].
\]

它不是预期SOTA，而是快速、稳定、可解释的最低参考线。

### 3.4 拆分

同一编号目录下的整篇论文数据只能进入训练或测试的一侧，避免同一论文不同CSV中的重复候选、EC50/SPR配对测量或近邻突变序列泄漏。正式实验还应增加抗原序列聚类拆分和抗体序列聚类拆分。

## 4. 计划中的高级模型

主模型采用抗体—抗原双塔编码加交叉注意力：抗体端分别编码重链、轻链和CDR，抗原端编码全序列和表位；结构存在时用等变图网络编码界面几何。训练损失为：

\[
L=\lambda_r L_{rank}+\lambda_y L_{reg}+\lambda_c L_{contrast}
+\lambda_s L_{structure}+\lambda_d L_{developability}.
\]

- `L_rank`：同靶点候选对的排序损失；
- `L_reg`：标准化分数回归；
- `L_contrast`：匹配抗体—抗原对的对比学习；
- `L_structure`：界面距离/结构置信度辅助损失；
- `L_developability`：可开发性辅助任务。

## 5. 先进性与技术价值

- 不把异构实验数据错误合并为单一绝对标签；
- 以排序作为主要学习目标，更符合候选筛选实际需求；
- 同时考虑抗原条件和抗体重轻链；
- 将昂贵结构计算放在后级漏斗，提高计算效率；
- 用Pareto筛选而非单一加权总分，保留不同权衡的候选。

## 6. 局限

- 当前实现只是序列基线，尚未训练高级生成器；
- 大量来源缺少抗原序列，不能证明跨抗原泛化；
- 公开标签混合真实测量和计算预测，必须分层报告；
- 计算亲和力或结构分数不能证明真实中和活性；
- 最终治疗候选必须经过实验和安全性验证。
